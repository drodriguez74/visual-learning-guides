mod.01 — context & CLAUDE.md

What loads eagerly vs. on demand

CLAUDE.md is paid for on every single turn, whether it's relevant or not. Skills and MCP schemas are deferred — they only cost tokens once something actually triggers them. This is the whole game of keeping a session cheap.

What belongs in CLAUDE.md

Facts and standing rules that apply to every session — architecture conventions, "TypeScript/Playwright, not Selenium," where things live. Not procedures you invoke occasionally (that's a skill), not one-time instructions (that's your prompt), not large reference material (link it, or make it a skill's supporting file). A section that reads like a runbook — "first do X, then check Y" — is a sign it should move to a skill instead.

Degradation, in one sentence

If Claude "forgets" a rule from 40 turns ago, that's compaction working as intended, not misbehaving — the fix is writing the rule down (CLAUDE.md) or enforcing it deterministically (a hook), not repeating yourself more forcefully.

mod.02 — permission modes

The same five actions, five different modes

Pick a mode. Watch what happens to the same set of actions. The tradeoff is never "safe vs. fast" — it's which specific things stop asking, and which stay guarded no matter what.

Protected paths — .git, .claude, .mcp.json, shell rc files — are the one row that never fully clears, in any mode except the one built for isolated containers.

mod.03 — subagents, forks & teams

Three ways to hand off work — and what each one remembers

The question that actually matters isn't "which is more powerful," it's what context does the worker start with. That answer changes what you have to tell it.

starts withown system prompt + delegation message Claude writes + CLAUDE.md + git snapshot
does NOT seeyour conversation history, files already read

Solves: context pollution. A search or log dump that would flood your main window gets isolated — you get a summary back, not the raw material.

Misuse: assuming it "knows what we've been discussing." It doesn't — vague delegation makes it research from scratch.

starts withthe ENTIRE parent conversation — same system prompt, tools, model, full history
stays isolatedits own tool calls — only the final result returns

Solves: "a subagent would need too much background to be useful." No re-briefing required — and the first request reuses the parent's prompt cache, so it's cheaper than it looks.

Use it when: the task genuinely needs everything discussed so far — e.g. drafting a regression test for a bug you just spent 20 turns diagnosing.

starts witha fully separate Claude Code instance, own context window, own CLAUDE.md/skills
does NOT inheritthe lead's conversation — you must give task context explicitly

Solves: work that benefits from perspectives arguing with each other, not just running in parallel — teammates message each other directly and self-claim from a shared task list.

Misuse: reaching for this by default because it's new and impressive. Anthropic's own docs say a single session or a subagent is more effective for anything sequential — teams cost real tokens for the coordination.

mod.04 — hooks

The exit code is the entire contract

A hook's shell command signals through its exit code — nothing else. Try each one. Notice which code most people assume works, and doesn't.

Pick an exit code above.

Where it actually gets enforced

Only events with real prevention semantics can block: PreToolUse, PermissionRequest, UserPromptSubmit. PostToolUse fires after the action already happened — good for logging or telling Claude the result was bad, useless for stopping it. And the if filter is best-effort: it fails open on unparseable Bash syntax, so it's a convenience filter, not a security boundary — that job belongs to permission deny-rules.

mod.06 — model & effort

Effort is a dial, not a toggle

Model tier picks which mind is working. Effort picks how hard it thinks per step, independent of the model. Drag the dial.

lowmediumhighxhighmax

high is the default on Sonnet 5 / Opus 4.8 / Fable 5 for a reason — don't move the dial without one. ultrathink in a single prompt borrows xhigh-style depth for one step without changing the session setting.

mod.07 — headless mode

Same engine, one flag changes what loads

$ claude
# loads your ~/.claude hooks, project CLAUDE.md, skills, MCP — waits for you at every prompt
$ claude -p "check coverage floor"
# STILL loads your full local config — usually right for a personal script, usually wrong for CI
$ claude --bare -p "check coverage floor" \
  --allowedTools "Read,Bash(cat *)" \
  --output-format json
# only flags you pass explicitly apply — a teammate's stray hook can't touch this run

The bug people hit isn't "headless is missing a feature" — it's forgetting that -p alone still inherits whatever's sitting in ~/.claude on the machine running it.

mod.08 — security & compliance boundaries

What's actually enforced by the platform vs. by you

R/Wworking directory + subtreeDefault read/write scope. Files outside it are readable with permission, never written.
BLOCKED.git, .claude, .mcp.json, shell rc filesProtected in every mode except the one built for isolated containers. Structural, not policy.
YOUR JOBe.g. payment-processing/ (PCI scope)No native data-classification concept. Enforce with deny-rules + hooks — the platform gives primitives, not policy.

Tool results — fetched pages, MCP responses, file contents — are treated as data, never instructions. That's why a hook's additionalContext should read as a fact ("this repo uses bun test") rather than a command — imperative phrasing trips the same defense meant to catch injected instructions.

synthesis

What actually separates the leverage

1. Context is the scarce resource — everything else is that discipline, applied six ways

CLAUDE.md, skills, subagents, forks, and compaction are all answers to one question: does this token deserve to be in front of the model right now? Ask it before writing anything down.

2. Hooks as policy infrastructure, not a linter trigger

Most "hook users" run a formatter after edits. Real leverage treats hooks as the deterministic backbone under everything probabilistic — enforcement, audit logging, self-correction loops. More setup cost, which is exactly why it's underused.

3. Choosing orchestration shape by dependency structure, not novelty

Agent teams look impressive. They're right for a genuinely ambiguous, adversarial-benefit problem and overkill for almost everything else. The skill is recognizing the minority case, not defaulting to the shiny one.

Honest caveat

A lot of "levels of context engineering" content is post-hoc narrative on a small number of real mechanisms: persist, isolate, or defer. Understand those three verbs and you have the substance — frameworks past that are mostly vocabulary.
